# ADR-0017 — Tez montaj from the chat; an uploaded music file as a ducked bed

**Why.** The owner works in Telegram. Uploading 300 MB phone clips needs the Mini App (the Bot API downloads at most 20 MB per file without running a local Bot API server), but once the material is in, nothing else needs the app: the result is a video in the chat. Social cuts also usually carry music under the voice, and the spec asks that music always yields to speech ("Voice music'dan ustun turadi. Music avtomatik duck qilinadi"). There is no licensed music library yet.

**Impact.**
*Chat.* The "speech ready" notification carries a "✂️ Tez montaj" button (`callback_data` `tm:<project id>`), and `/montaj` starts it for the latest project. Both go through `synthcut_core.renders.start_auto_edit_async` — the same readiness rules and one-request-at-a-time guard as the API — with the owner's remembered settings and delivery to the chat forced on. When the owner waits in the chat, a failed plan, a failed render or a QA block is reported there too.
*Music.* An audio asset of the project whose transcript has under 25 % speech (or none) is a music file; Tez montaj takes the longest one (`music` / `music_gain_db` in the remembered settings; feedback "Musiqa baland / past / kerak emas"). The plan gets an `audio_tracks` entry with role `music`: the file repeated to cover the cut, 1 s fade-in, 2 s fade-out, 0.5 s fades at the joins, and timeline `ducking`. The renderer reads each music clip from the original (`-ss`/`-t` per clip, so nothing is buffered), applies gain and fades, places it with `adelay`, ducks the sum under the voice with `sidechaincompress` keyed by the voice chain, then adds effects and normalises loudness over the whole mix (both loudness passes see the music). Other audio-track roles and library music are still refused with a reason. A song with lyrics reads as speech and is not used as a bed.

**Alternatives.** Uploading through the bot (20 MB limit, or a local Bot API server as one more service); ducking with volume automation from VAD spans (sidechain compression reacts to the processed voice itself and needs no second analysis); a bundled royalty-free library (licences to review first — a `library_id` source is already in the contract).

**Decision.** Chat start through the same core path as the API; music from the owner's own upload, ducked by a sidechain compressor in the master and loudness passes.
