# ADR-0019 — The AI team edits on top of the rules draft, through declarative tools

**Why.** The Director and Editor agents (spec §14-27) must produce timelines an editor would: story order, hook, punch-ins, cutaways, transitions, speed, graphics. Asking a model for a whole EditPlan in timeline seconds invites arithmetic errors, overlaps and gaps; starting from nothing wastes what the rules editor already measured (speech, pauses, unusable shots, faces, grades, the voice mix).

**Impact.**
*Provider.* `synthcut_model_router.providers.anthropic` uses the official SDK: streamed requests read with `get_final_message()`, adaptive thinking (thinking blocks carried back verbatim as `ProviderBlock` with the tool results), automatic prompt caching of the stable prefix (system prompt + sorted tools), `eager_input_streaming` on client tools (every input is validated by its Pydantic model anyway), errors mapped to `ProviderError` with failover only where another target can help. Routes stay configuration (`MODEL_ROUTES`), default `anthropic:claude-opus-5`.
*Tools.* 19 of the 34 catalog tools have handlers (`synthcut_agents.runtime.tools`): reads (project context, transcript with optional word timings, shot analysis, media metadata, plan, validation, motion registry, preferences), writes (create / update plan, graphics, captions, grade, mix, QA findings) and render requests. Writes are declarative (`PlanEdit`): the main track is the story in order — asset, source range, speed, how the clip arrives, placement, keyframes — and `planedit.apply_edit` lays it end to end on the frame grid, inheriting framing and grade per asset from the base and rebuilding the music bed for the new length. Nothing is saved unless `validate_plan` passes; the issues go back to the model.
*Orchestration.* `runtime.orchestrator.run_ai_edit` plays the Master in code: Director (story) → Editor (polish) → Motion → QA, plus one Editor fix round when QA reports errors. Each run gets only its manifest's tools, a share of one budget (`AGENT_BUDGET_USD`), and is recorded in `agent_runs` (status, steps, tokens, cost, tool calls, versions written, findings, its summary for the owner). The prompts carry a house style (hook first, punch-ins on jump cuts, cutaways, sparing transitions, speed only on non-speech).
*Product.* `POST /projects/{id}/ai-edit` (a rules draft first when there is no plan), `agent.edit` on the `llm` queue, render and delivery as for any plan; `GET /ai/status`, `GET /projects/{id}/agent-runs` for the AI Decisions tab. Without a key the endpoint refuses with a reason and Tez montaj keeps working.

**Alternatives.** A model writing whole plans from scratch (timing errors, no reuse of measurements); a Master agent choosing the order with its own model calls (cost and variance for a fixed sequence); the SDK's tool runner (our loop must gate every call by agent manifest and work with any provider behind the router — ADR-0009).

**Decision.** Rules draft → agents edit declaratively → the system lays out and validates → render; every agent's work recorded and shown.
