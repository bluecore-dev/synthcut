# ADR-0018 — The timeline renders in pieces: one FFmpeg run per constant set of layers

**Why.** An editor's timeline is more than cuts: transitions overlap two clips, cutaways and picture-in-picture sit on top, speed changes stretch time, keyframes animate framing, J / L cuts move sound off its picture. The first renderer (ADR-0015) rendered one clip per run and refused the rest. One FFmpeg graph for the whole timeline would open every source at once (the memory trap ADR-0010 recorded) and report no useful progress.

**Impact.** `synthcut_timeline.pieces.plan_pieces` cuts a validated plan wherever what is on screen changes — clip edges, transition windows, overlay edges — so inside each piece the layers are constant: one main clip or a transition between two, plus overlays in track order. Each layer knows the source second at the piece's first frame and how far into its item that is (keyframe time). `synthcut_media.compose.piece_command` renders one piece with a fixed graph: `xfade` / `acrossfade` for transitions (crossfade, dip to black / white, whip, zoom), `setpts` / pitch-keeping `atempo` for speed, `perspective` with per-frame eased expressions for zoom and pan (sub-pixel smooth, unlike `zoompan`), `overlay` with keyframed position and `fade` / alpha for cutaways and picture-in-picture, black for empty stretches; exact frames and samples into the same intermediate as before, so pieces join with the concat demuxer. The sound bus (`synthcut_media.final.Sound`) takes the timeline's own audio plus voice-track clips through the voice chain (J / L cuts), ducks music and ambience under it, adds SFX clips and cues, then normalises loudness; volume keyframes are per-frame `volume` expressions. Still refused with a reason: rotation and overlay-size animation, opacity curves other than fades, library audio; `validate_plan` rejects an overlay that starts or ends inside a transition (`E_TRANSITION_SPLIT`), because a transition renders as one blend.

**Alternatives.** One graph for the whole timeline (memory, no resumable progress); MLT / melt (a second timeline model, no per-step progress); `zoompan` for keyframed zoom (integer offsets: visible jitter on slow zooms); per-pixel `geq` for opacity curves (several times slower than `fade` and `lut`).

**Decision.** Pieces with constant layers, each a bounded FFmpeg run, joined exactly; every primitive measured on pixels and samples in the tests.
